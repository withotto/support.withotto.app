The client missing receipts page is where a client answers the questions their accountant or bookkeeper has about their bank payments. It lists the payments on the client's current list, and the client answers each one by sending a receipt or invoice, writing a short note, or both. There's nothing to download and no Otto Capture account to create.

This guide is written for the practice. For importing transactions and choosing what the client is asked about, see [Missing receipts](/capture/missing-receipts/).

## Sharing the link

Each client has its own link, created when an admin [turns the page on](/capture/missing-receipts/#turning-it-on-for-a-client). Anyone in your organisation can copy it from **See answers** on the client's **Missing receipts** tab, or from **Client submission** in the client's settings.

<ZoomableImage
  src={settingsPanel}
  alt="The Client missing receipts page area of a client's settings, showing the link with a Copy link button, then Rotate link and Turn off client missing receipts page, above a panel headed What your client will be able to see"

Share it directly with whoever at the client can find the receipts. Capture doesn't send the link or tell the client when their list changes, so let them know. The same link works every time, and shows the latest list when it's opened.

The page shows your organisation's name and each payment's date, bank account, description, and amount. It shows nothing else about the client's books: no document statuses, nothing about imports or excluded transactions, and not the client's own name.

## How a client answers a payment

For each payment, the client can send a file, write a note, or both. A note on its own is a complete answer for a payment the client has no document for.

### Files not linked to a payment

A file ends up under **Not linked to a payment** when the client removes it from a payment, you use **Ask again**, or you take its payment off the list. The client can put it back on a payment that still needs a file.

  src={notLinked}

  label="Not linked to a payment section"

A file the client removes still stays in Capture, and counts towards billing like any other document if you publish it. If you discard a file the client sent, or Capture detects it as a duplicate, its payment shows as unanswered again so the client can send another.

## What anyone with the link can see

Anyone holding the link can see the date, amount, description, and bank account of every transaction on the client's current list, and can answer them. There's no login, and the link isn't restricted to an email address or a domain.

That makes this link more sensitive than a [submission link](/capture/getting-started/client-submission-page/#treat-the-link-like-a-key), which only lets someone send documents in. Bank descriptions routinely name people, suppliers, and salaries, so treat the link like a key, and use the list to keep off anything the client doesn't need to be asked about.

Search engines are told not to index the page, and the link isn't passed on to any other site the client might visit next.

## Rotating and turning the page off

Both actions are in the client's settings under **Client submission**, and both are admin-only.

- **Rotate link** replaces the link straight away. The client's list is unchanged, and anyone who should still be answering needs the new link.
- **Turn off client missing receipts page** removes the link and the **Missing receipts** tab until an admin turns the page back on. The stored transactions and the client's list are kept.

Turning the page back on creates a fresh link. A link you've rotated away or turned off stays dead, so an old one can never come back.

## What breaks a link, and what doesn't

| Change                                         | Effect on the link                                                                       |
| ---------------------------------------------- | ---------------------------------------------------------------------------------------- |
| Changing the client's name or prefix           | Keeps working. The address updates itself when the page is next opened                   |
| Changing your organisation prefix              | Breaks every client's link. Share the new ones                                           |
| Disconnecting the client's accounting platform | Stops working. The same link works again once the client is reconnected and set up again |
| Rotating the link, or turning the page off     | Breaks the old one immediately                                                           |

<Aside type="caution">
  A disconnected client's link is dormant, not dead: it works again once the
  client is reconnected and set up again. If you've disconnected a client
  because a link may have leaked, rotate it or turn the page off as well. Both
  still work while the client is disconnected.
</Aside>

## Spam protection

The page shares the client submission page's limit against misuse, set well above normal use. If a client tells you they're hitting it, please contact support.
